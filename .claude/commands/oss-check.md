# Open-Source Readiness Check

Review all commits on the current branch (vs main) to ensure they are ready for public open-source release.

## Process

### 1. Identify Commits to Review

Run `git log main..HEAD --oneline` to see all commits that will be made public. Also run `git diff main..HEAD` to get the full diff.

### 2. Secrets & Sensitive Data Scan

Search the full diff for:
- **Hardcoded credentials**: API keys, tokens, passwords, secrets (patterns like `sk-`, `ghp_`, `AKIA`, `Bearer <real-token>`)
- **Internal URLs**: Private hostnames, IP addresses, internal service URLs (anything not `localhost`, `example.com`, or well-known public domains)
- **Personal information**: Email addresses, private names, phone numbers
- **Private infrastructure**: Internal tool names, private repo references, VPN endpoints
- **Environment leaks**: Hardcoded env-specific paths, database connection strings

### 3. Example URL Validation

Check all URLs in the diff:
- Example/placeholder URLs should use `example.com` (RFC 2606)
- Real third-party service URLs (e.g., `notion.com`, `stripe.com`) are OK in docs if used as illustrative examples
- Flag any URLs that appear to be internal or private

### 4. Commit Message Quality

For each commit, check:
- **Conventional commits format**: `type(scope): description`
- **Accurate type**: `feat` for features, `fix` for bugs, `test` for tests, etc. Flag mismatches.
- **Clear description**: Explains the "why", not just the "what"
- **No AI attribution**: No "Generated by AI", "Co-Authored-By: Claude", etc. in messages
- **No WIP/fixup**: No temporary commit messages

### 5. Commit Hygiene

Check for:
- **Fixup commits**: Later commits that just clean up earlier ones (should be squashed)
- **Mixed concerns**: Single commits bundling unrelated changes
- **Broken bisectability**: Commits that would fail to build/test if checked out individually
- **Logical ordering**: Dependencies should come before dependents

### 6. Code Quality Concerns

Scan the diff for:
- **Debug artifacts**: `console.log` for debugging, commented-out code, TODO/FIXME/HACK
- **Unused imports**: Added but not used
- **Test skips**: `.skip` or `.only` left in test files (flag these, they may be intentional)

### 7. License & Package Check

Verify:
- LICENSE file exists and matches `package.json` license field
- No `private: true` in `package.json`
- `files` field or `.npmignore` prevents source/test leakage into published package
- No `.env` files or credential files tracked in git

## Output Format

Report findings in a table grouped by severity:

| Severity | Category | Finding | Location |
|----------|----------|---------|----------|
| CRITICAL | ... | ... | file:line |
| WARNING | ... | ... | file:line |
| INFO | ... | ... | file:line |

- **CRITICAL**: Must fix before pushing (secrets, broken history)
- **WARNING**: Should fix (misleading messages, debug artifacts, mixed commits)
- **INFO**: Minor suggestions (could improve but OK to ship)

End with a clear **PASS** / **FAIL** / **PASS WITH WARNINGS** verdict.

If FAIL or PASS WITH WARNINGS, suggest specific fixes (squash plan, files to edit, etc.).
